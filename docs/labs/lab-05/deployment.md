## 1. Stack, and what differs from the reference

The reference stack from the Student Guide (Episode 0.2), unchanged:
React 18 + Vite and Express + TypeScript on Node.js 24, Prisma 5 and
PostgreSQL 16; Artifact Registry, Cloud Run, Cloud SQL for PostgreSQL, Secret
Manager, GitHub Actions with Workload Identity Federation.

Changes from the Starter Kit, each with its reason:

| Change | Reason |
|---|---|
| `Dockerfile` copies `server/src/lib/password-policy.ts` into the client build stage | The client re-exports the shared password policy from the server (`client/src/auth/password-policy.ts`). Without that file `tsc` / `vite build` fails. |
| `CMD ["node", "dist/src/index.js"]` (kit: `dist/index.js`) | `server/tsconfig.json` also compiles `prisma/` and `tests/`, so the entry point is `dist/src/index.js`. `npm start` was corrected the same way. |
| `ARG APP_COMMIT` in the Dockerfile, `GET /api/version` in the API | R-08: the live URL reports the commit it was built from. A rollback redeploys an older image, which reports its own older SHA. |
| One `docker-compose.yml` service runs the production image (kit: separate API and nginx client images) | The local run is the same image Cloud Run runs, so C-03 checks what is deployed. `client/Dockerfile`, `server/Dockerfile` and `nginx.conf` are not used. |
| `docker-compose.yml` takes every password from `.env` (`${VAR:?}`) | The kit had default passwords in the file; the repository is public. |
| `ci-docker.yml` runs on Pull Requests into `staging` and `main` (kit: `main` only) | Handout R-05 and the Definition of Done: CI on every PR into both. |
| `deploy/smoke_test.py` signs in with the `tt_session` cookie (kit: Bearer token) and checks `/api/version` | TokTickIT sessions are an HttpOnly cookie. The commit check makes a release fail if an older revision is still serving. |
| Kit guides moved to `docs/labs/lab-05/kit-guides/` | They are the TA team's reference, not this team's documentation. |

## 2. Environment variables

Every setting comes from the environment. Nothing real is committed: `.env`
is in `.gitignore`; only `.env.example`, `server/.env.example` and
`client/.env.example` are tracked, with placeholders.

| Variable | Read by | Purpose | Secret? | Local value from | Cloud Run value from |
|---|---|---|---|---|---|
| `DATABASE_URL` | server, migration job | PostgreSQL connection string | **Yes** | `server/.env` / compose builds it from `POSTGRES_PASSWORD` | Secret Manager `toktickit-database-url` (via the Cloud SQL socket) |
| `PORT` | server | Listening port | No | default 3000 | Cloud Run injects it; image default 3000 |
| `NODE_ENV` | server, seed | `production` turns on: Secure cookie, serving the built client, passwords from env in the seed | No | unset (development) | Dockerfile + `deploy.sh`: `production` |
| `TZ` | server | Time zone for dates | No | — | `Asia/Bangkok` |
| `ATTACHMENT_STORAGE` | server | `disk` = files under `UPLOAD_DIR`; `database` = bytes in `Attachment.content` (R-04) | No | `disk` (default) | Dockerfile + `deploy.sh`: `database` |
| `UPLOAD_DIR` | server | Folder for attachments in disk mode | No | `uploads` | not used |
| `MAX_UPLOAD_BYTES` | server | Upload size limit | No | 5242880 | default 5242880 |
| `CLIENT_ORIGIN` | server | Extra origin allowed to send writes (CSRF check) | No | `http://localhost:5173` | not set: the service accepts its own https origin |
| `CLIENT_DIST_DIR` | server | Where the built React app is | No | not set | image default `../client/dist` |
| `APP_COMMIT` | server | Commit SHA returned by `/api/version` | No | not set (`unknown`) | Docker build arg from `deploy.yml` (`github.sha`) |
| `ADMIN_PASSWORD` | seed (production) | First Administrator `panida.s@example.ac.th`, must change at first sign-in | **Yes** | `.env` (compose) | Secret Manager `toktickit-admin-password` (generated by `deploy.sh`) |
| `SEED_DEMO_DATA` | seed (production) | `true` also seeds demo personas and tickets for the Lab 6 partner team | No | `.env` (compose) | `deploy.sh --demo` sets `true` on the migration job |
| `DEMO_USER_PASSWORD` | seed (production) | Password of every demo persona | **Yes** | `.env` (compose) | Secret Manager `toktickit-demo-password` (generated) |
| `POSTGRES_PASSWORD` | compose only | Local database password | **Yes** (local) | `.env` | not used |
| `VITE_API_URL` | client build | API base URL; empty = same origin | No | `""` | `""` (Dockerfile) |

## 3. What changed in the application for the cloud (Episode 2)

### 3.1 The six points

| Works locally, breaks in the cloud | What TokTickIT does now | Test |
|---|---|---|
| Sessions in memory | Already a `Session` table since Lab 3 | Lab 3 auth tests |
| Uploaded files on the container disk | `ATTACHMENT_STORAGE=database`: bytes in `Attachment.content` (migration `20261112090000_lab05_attachment_content`, additive, nullable). Rows from disk mode still download from disk. | LAB5-02, LAB5-03 |
| Passwords in code | Production seed reads `ADMIN_PASSWORD` / `DEMO_USER_PASSWORD`; refuses to run without them. The development passwords in `graded-seed.ts` are never used when `NODE_ENV=production`. | LAB5-04..07 |
| Reference data and first admin created by hand | Seed creates categories, related systems and the Administrator (`mustChangePassword: true`) | LAB5-06 |
| `http://localhost` assumptions | Cookie gets `Secure` in production; `trust proxy` so `req.protocol` is https behind Cloud Run; writes from the service's own origin are accepted, any other origin still 403 | LAB5-08, LAB5-09 |
| Client served by Vite | In production the API serves `client/dist` and returns `index.html` for any non-`/api` GET (deep links work) | checked by smoke test `/` |

### 3.2 Two new public routes

Both are read-only and return no user data. The Lab 3 SEC-01 and Lab 4 SEC-09
route-inventory tests list them explicitly.

| Route | Returns | Used by |
|---|---|---|
| `GET /api/ready` | `200 {"status":"ready","db":"connected"}` or `503` | smoke test: the service reaches Cloud SQL |
| `GET /api/version` | `{"commit":"<SHA>"}` | smoke test and R-08 |

## 4. Commands

Run from the repository root unless noted.

| Task | Command |
|---|---|
| Install | `cd server && npm ci` ; `cd client && npm ci` |
| Migrate | `cd server && npx prisma migrate deploy` |
| Seed | `cd server && npm run prisma:seed` (idempotent) |
| Test (server) | `cd server && npm test` — needs `DATABASE_URL`; creates its own `toktickit_test` database |
| Test (client) | `cd client && npm test` |
| Test (deploy scripts) | `bash deploy/tests/test_deploy_stub.sh && bash deploy/tests/test_release_stub.sh && python3 -m unittest discover -s deploy/tests -p 'test_smoke.py'` |
| Run (development) | `cd server && npm run dev` and `cd client && npm run dev` → http://localhost:5173 |
| Build the image | `docker build --build-arg APP_COMMIT=$(git rev-parse HEAD) -t toktickit:local .` |
| Run the image with its database (C-03) | `cp .env.example .env` (fill in values) then `docker compose up --build` → http://localhost:3000 |
| Smoke-test any URL | `python3 deploy/smoke_test.py http://localhost:3000` |
| First cloud deploy | Cloud Shell: `DRY_RUN=1 PROJECT_ID=<PROJECT_ID> bash deploy/deploy.sh --demo`, read it, then without `DRY_RUN` |
| Tear down (end of course) | `bash deploy/teardown.sh` |

## 6. Release procedure (R-07, R-08)

Only `main` deploys, so every merge into `main` is a release.

1. Open an Issue labelled `lab5`; branch `feature/<n>-<slug>` from `staging`.
2. Pull Request into `staging`. CI (`test-and-docker`) runs. The teammate
   reviews with a specific comment; the author never approves their own PR.
3. Merge into `staging`.
4. Release Pull Request `staging` → `main`, labelled `lab5`. CI runs again;
   the ruleset blocks the merge unless `test-and-docker` passes, the branch is
   up to date, and a PR is used.
5. Merge. **Deploy demo** (`deploy.yml`) starts on the push to `main`: CI
   again → build the image tagged with the full commit SHA, `APP_COMMIT` baked
   in → push → `deploy/release.sh` resolves the digest, runs the
   `toktickit-migrate` job, updates the service by digest → smoke test,
   including `/api/version` = the SHA.
6. Record the release: the run summary shows the commit, digest and URL.

**Which commit is running** — any of:
- `curl <URL>/api/version` → the full SHA;
- Actions → latest successful "Deploy demo" run → summary;
- `gcloud run services describe toktickit --region asia-southeast1 --format='value(spec.template.spec.containers[0].image)'` → the image digest, which `gcloud artifacts docker images list asia-southeast1-docker.pkg.dev/<PROJECT_ID>/toktickit/toktickit --include-tags` maps to its SHA tag.

**Rollback** — Actions → Deploy demo → Run workflow on `main` with
`image_tag` = the full SHA of the last good release. Tests, build and migration
are skipped; that image is deployed and smoke-tested. Migrations are additive,
so the older image runs on the newer schema. Then fix forward through a normal
PR.

## 7. Cost control

Budget alert before any resource. Cloud Run scales to 0. Cloud SQL bills every
hour it exists (about USD 14–18 a month, TA estimate): stop it when idle with
`gcloud sql instances patch toktickit-pg --activation-policy=NEVER` and start it
again with `--activation-policy=ALWAYS` (Episode 9). Keep the service running
until grading ends, then `deploy/teardown.sh` (Episode 10).
